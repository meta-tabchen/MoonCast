# MoonCast 0.3.0 使用说明

Android 手机作为 Moonlight 局域网发射端，接收端使用官方 Moonlight。普通投屏不需要电脑、Root 或 ADB。APK 是使用本地 debug 密钥签名的预览版；升级前请确认签名，卸载会清除配对记录。

## 首次连接

1. 手机安装 Release 中的 APK，接收端安装官方 Moonlight，连接同一可信局域网。
2. 手机点「启动投屏」，批准共享整个屏幕。
3. Moonlight 发现手机，或手动添加 MoonCast 显示的手机 IP。
4. 把接收端显示的四位 PIN 输入手机配对框。
5. Moonlight 打开 `Desktop`，手机切换到视频或应用。
6. 在手机或通知栏停止。普通投屏断开后保留共享：传输层重启时显示「正在准备重连」，就绪后显示「等待重新连接」。单接收端模式的新连接会替换尚未退出的旧会话；主动停止后再启动才重新申请共享授权。配对记录保留。

先尝试 H.264／HEVC、1080p60、30–50 Mbps，分辨率／帧率／码率在 Moonlight 设置。手机硬件编码器、接收端解码器和网络决定上限，没有 4K60 或无损编码承诺。

## 画面模式

| 模式 | 行为 |
| --- | --- |
| 整个手机屏幕 | 保留全部屏幕与原比例 |
| 自动去黑边 | 检测近黑色外边框，持续更新；检测仍为启发式 |
| 视频铺满 | 铺满接收端，可能裁掉视频内容 |
| 固定中央 16:9 | 横屏直接截取中央最大 16:9，无需框选；竖屏保留整屏 |
| 智能影院 | 每 250 ms 采样，八次稳定结果后锁定；浮层与暗场不再改变已锁定区域 |

智能影院内容变化时点「重新检测视频」，旋转或切换模式也会重置。它不会查询第三方播放器的视频 Surface，偏移视频、其他比例和深色场景仍需要验证。原有四种模式保留，可在投屏中切换。4:3 iPad 要完整显示 16:9 视频，必要的上下黑边仍然存在；铺满会裁边。

## 接收端配置与实时面板

启动前选择通用／iPad／电视／电脑配置，分别保存显示、音频、编解码偏好和反控设置。这是手动选择，不会自动识别客户端身份。

观影／游戏／省电预设分别限制捕获提交到 60／120／30 FPS，不修改 Moonlight 的请求码率或分辨率，也不自动授予音频／输入权限。面板显示应用 UID 上行流量、捕获提交帧率、CPU／驱动提交耗时、电池温度和系统温控状态。它不代表接收端帧率、GPU 实际耗时或端到端延迟；Root 捕获进程不属于应用 UID，面板明确标为不可用。

## 播放声音与本地静音

Android 10+ 可开启播放声音捕获，需要音频权限和源应用允许捕获；不使用麦克风。可选本地静音只在接收端请求音频且捕获成功后生效，只调整媒体音量，不改铃声／闹钟。

停止、捕获失败时恢复原音量；恢复记录支持进程异常退出后下次启动重试。用户主动调到非零音量时会保留新设置。实际手机是否「本地无声、接收端有声」取决于 ROM，需要真机验证。Root 屏幕捕获和独立应用显示目前仅视频。

## 单应用与独立应用显示

Android 14+ 的「单应用」通过系统授权选择一个应用，不投完整桌面。系统不提供窗口位置映射，因此此模式关闭反控。

「独立应用显示」需要另外安装、启动并授权官方 Shizuku。连接接收端后用「打开独立显示应用」选择应用，应用运行在单独的虚拟显示上，手机主屏可做其他事。首次接收端决定显示尺寸，后续接收端可能缩放该显示；只发送视频。应用可能拒绝副显示、受保护内容或启动；该模式为实验功能。

## 可选远程操控

默认关闭，用户明确开启后才接收输入。画面与触摸采用同一坐标映射，比例黑边内的点击忽略；停止时取消触摸、释放按键。

- 无障碍：在系统设置启用 MoonCast 服务。点击、单指滑动在抬手后执行，支持返回／主页／最近任务；不读取窗口文字，不支持任意键盘输入、持续按住或多指。
- Root：明确授予 `su`，单独的 UID-0 输入进程支持持续触摸、最多十点和基础键盘；普通 MediaProjection 也可以配合 Root 输入。
- Shizuku：另外安装、启动官方 Shizuku 并授权 MoonCast，通过拥有者绑定的特权服务注入持续触摸与基础键盘。

单应用授权和多人观看模式关闭反控。Root 屏幕捕获使用 Root 注入。手柄、滚轮和右键未实现。先在整屏模式测试，再检查裁切／旋转后的坐标。系统已提交的无障碍手势可能继续到结束。

## 原文件影院

选择一个视频／照片／音频文件，复制显示的局域网链接，在接收端的兼容浏览器打开。文件字节原样传输，不经过录屏或转码；浏览器的容器、编解码、HDR 与色彩支持仍决定播放效果。Moonlight 不播放这个文件链接，这不是 DLNA，也不提取 DRM 内容。

支持单个字节范围、定位播放和 HEAD；未知长度的文档提供者只能流式读取。选择新文件会关闭旧链接并换令牌，「停止分享」或通知栏停止会断开读取并撤销链接。持有有效链接的人都能读取所选文件，请仅在可信局域网使用。文件分享和投屏分别停止。

## 多人观看（实验）

启动前开启，允许最多三个接收端共用一次捕获、同时输出各自尺寸。共用显示模式，要求相同音频包时长，并关闭反控。每个接收端增加一个编码器，手机并发编码能力和网络带宽可能不足。在接收端列表可单独断开一个。

MuMu 已验证不同尺寸的 GPU 多输出与输出移除后其他画面继续，但模拟器没有兼容的硬件 AVC 编码器，无法完成两路编码／传输／解码验收。完整串流、单独原生断开和共用音频仍需真机验证。

## 投屏时关闭本地屏幕（实验）

每次启动前单独开启，默认不记住。需要 Root 屏幕捕获或已授权的 Shizuku，且独立于反控开关。已有画面输出后调用物理屏幕电源 API，保持 Android 处于唤醒状态，不发送锁屏／休眠按键，不修改安全锁屏设置。

「恢复本地亮屏」、停止、最后接收端退出、捕获异常和拥有者丢失会尝试恢复。每五秒更新心跳，缺失 30 秒后租约到期，恢复失败会保留待恢复状态重试。设备 API 不支持或物理面板选择存在歧义时拒绝操作。强杀特权服务本身、驱动或系统故障可能阻止软件恢复，可用实体电源键恢复。

MuMu 的 Shizuku 电源接口、保持唤醒、手动恢复、超时和清理测试通过；Root 有界接口／恢复探测通过。模拟器不能证明真实面板熄灭、继续播放或节省电量，折叠屏与 ROM 行为仍待测试。

## 构建、诊断与验证

JDK 17、Android SDK 35、Build Tools 35.0.0。Windows 用 `gradlew.bat`。

```sh
./gradlew :app:assembleDebug :app:lintDebug
python scripts/run_unit_tests.py
python scripts/verify_apk.py app/build/outputs/apk/debug/app-debug.apk
```

默认使用固定的原生运行库；会话桥在 CI 中分别编译验证，完整 Sunshine 核心的 NDK 源码重建仍未验证。参见 [构建指南](building.md)、[逐项开发记录](feature-development.md) 和 [验证范围](validation.md)。

「连接与设备设置」包含编码器信息、生成测试画面和诊断。黑屏先检查共享授权、硬件编码参数和 DRM／FLAG_SECURE。反馈附应用、手机系统、Moonlight 版本、码率／帧率／分辨率和复现步骤；删除网络地址、证书、密钥、配对记录和私人屏幕内容。
