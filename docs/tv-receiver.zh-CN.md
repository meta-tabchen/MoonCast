# MoonCast TV 接收端（0.3.0 预览版）

这是独立的 Android TV 应用（包名 `com.mooncast.tv`），与仓库内原有手机发送端并存。请下载 GitHub Release 的 **TV APK**，不要当成手机发送端更新。

**版本范围：**本文记录已发布的 TV v0.3 AirPlay/DLNA 预览版。当前源码树另外已接入**未发布、测试中的
GameStream 接收路径**，使用手机 MoonCast 发送端并复用 TV 裁切，不是安卓系统投屏选择器支持；尚无
真实手机到电视端到端通过声明。见[内置 GameStream 说明](tv-gamestream.md#中文说明)。新 TV 发布由
[外部稳定签名门禁](tv-signing.md)控制，不改变历史 v0.3 资产与下文调试签名事实。

- 实现真实 UxPlay AirPlay 镜像 / 音频接收、无 PIN 连接与原生硬件解码；不是只注册一个设备名称。
- 实现 DLNA 设备发现、媒体地址播放、暂停、定位、音量 / 静音及状态事件。DLNA 不等于手机屏幕镜像。
- 支持保持比例、铺满、四边独立实时裁剪、缩放 / 平移、稳定黑边锁定与字幕区域扩展保护，以及自适应视频清晰度上限。
- 不支持或冒充 Google Cast、Miracast、AirPlay 2 多房间，也不绕过 DRM 或应用限制。
- 已发布的 TV v0.3 不含 Moonlight / GameStream 客户端；当前未发布源码已接入测试中的
  [H.264 SDR/立体声接收路径](tv-gamestream.md)，原有官方 Moonlight 接收方式仍可使用。
- 所有真实 iPhone / Android TV 互通与画音性能仍需验收；构建成功不等于全部设备已兼容。

## 使用

1. 在 Android 8.0+ 电视安装 TV APK（ARM64 / ARMv7，另含 x86_64 测试架构）。预览版使用调试签名；不同 CI 发布可能使用不同密钥，升级可能要卸载旧版，清除偏好与配对记录。尚未配置稳定正式签名升级。
2. 手机与电视接入同一可信局域网，打开应用即自动接收，无需点击启动。退出到后台会停止接收，下次打开会重新启动。
3. iPhone 从“屏幕镜像”选择电视显示的名称，无需输入 PIN；同一可达局域网内的设备可直接连接。DLNA 应用则选择该渲染器播放未加密的媒体。
4. 遥控器确认 / 菜单显示控制，首页提供“画面裁剪”“高级设置”和返回画面；画面 / 声音、连接恢复及调试信息收进高级设置。播放时返回打开菜单，默认焦点为「返回播放」；菜单再次返回会直接回画面，不停止播放。嵌套设置先关闭当前弹窗，编辑中返回仍取消本次预览。仅待机首页返回才询问退出。离开应用会停止所有接收，不会在后台继续监听。

同一时间只播放一个来源。DLNA 接管时会暂停 AirPlay 接收以避免声音重叠；停止媒体后恢复 AirPlay 发现。网络变化会停止旧播放并在新局域网重新发现。

## 安卓系统投屏为何看不到

安卓系统无线投屏与视频 App 的 DLNA 入口不是同一协议。本版修复了 DLNA 连续搜索被丢弃和较大 MX 被拒绝的真实兼容问题，但不会因此出现在仅支持 Miracast / Google Cast 的系统列表中。完整官方依据、普通 APK 的权限边界与可落地的 OEM 路径见[安卓系统投屏说明](tv-android-system-casting.md)。

## 遥控器实时裁剪

- **完整显示**保留全部画面，必要时留黑边；**铺满屏幕**等比放大并裁去超出屏幕的边缘。
- **实时裁剪 / 缩放 / 平移**以透明编辑层和小块半透明说明栏覆盖正在播放的画面。左、上、右、下分别调节 0–45%；每个方向至少保留原画面的 20%，因此一对相对边合计不能超过 80%。等比缩放为 100–300%，左右 / 上下位置为可移动范围的 −100%…+100%，不会拉伸变形。
  - 上下选择缩放、左右位置、上下位置或某条边；左右每次调节 1%，持续长按后每次调节 5%。
  - 确认保存；返回取消本次预览并恢复原设置。菜单键预览恢复完整画面，仍需确认保存，返回仍可取消。“画面裁剪”菜单中的“恢复完整画面”则直接保存 APP 全局的完整显示选择。
  - 首次默认自动去黑边，模式及手动边距 / 缩放 / 平移在整个 APP 共用并记住上次选择，不区分来源或横竖屏。自动识别出的坐标只属于当前视频，新视频 / 来源 / 尺寸会重新检测，不会套用上一段视频的黑边坐标。来源或尺寸切换会取消过期编辑。旧版配置没有最近修改时间，升级后尚无全局值时从自动开始，不任意猜测旧配置。只保存用户参数，不保存发送端身份、媒体名称或 URL。
- **自动去黑边**每秒采样两次 160×90 画面，检查成对黑边、画面内部亮度和边缘可见内容。普通黑边需连续 8 个稳定样本；宽黑边（例如横屏流中包含竖屏内容）需 12 个样本及更严格的证据。暗场和不确定样本不会触发新裁剪。
  - 锁定后不会自动继续收紧。连续两个样本发现被裁区域出现新内容时，会恢复该方向的边缘，帮助显示新字幕或浮层；这只是保护性启发规则，不保证识别所有字幕。
  - 内容变化后可选“重新检测黑边”。内嵌字幕随画面一起移动，手动裁剪 / 缩放可能隐藏字幕；需要时切回完整显示或恢复完整画面。

## 画面与声音

“媒体分辨率上限”只选择 Media3 现有轨道，可设自适应、最高 1080p 或 720p。“AirPlay 镜像设置”单独请求最高 1080p60、1080p30 或 720p60。这是协商偏好，不保证实际收到的分辨率 / 帧率，也不会恢复源画面丢失的细节或改变固定文件的编码。运行信息区分镜像请求值与解码器报告的尺寸、名称及输出统计；这些不是实际屏幕呈现或端到端延迟测量。

本版有两条独立音频路径：

- **媒体播放 / 音画校准**用于 Media3 媒体地址播放，包括 DLNA 和 AirPlay HLS。偏移为 −500…+500 毫秒，每次 50 毫秒，按 DLNA / AirPlay 媒体分别保存。正值插入静音 PCM 帧以延后声音；负值丢弃开头的 PCM 帧以提前声音，因此会损失对应的起始音频。每次新流 / 定位清空缓冲后应用一次。修改设置会从当前进度重建播放并保留播放 / 暂停选择；直播或不可定位的源可能回到可用的直播位置。
- Media3 **观影**模式缓冲媒体 8–30 秒，起播门槛 1 秒，再缓冲门槛 2 秒；**低延迟**模式分别为 1–5 秒、250 毫秒、500 毫秒，并使用 50–150 毫秒的较小 PCM 缓冲目标，仍受设备最低要求约束。这是真实缓冲设置，不是实测端到端延迟，弱网可能更容易卡顿。
- 校准走解码后的 PCM16 路径；即使偏移为 0，也禁止 HDMI 编码直通、音频卸载、浮点直出、隧道模式和跳过静音绕过处理器。仅能通过编码直通播放的格式可能无法播放，高精度源也可能损失额外精度。实现与测试说明见 [Media3 音频校准文档（英文）](tv-audio-calibration.md)。
- **AirPlay 音频抗抖动缓冲**用于独立的原生镜像 / 纯音频引擎。观影默认使用真实的 150 毫秒音频预缓冲，视频按源 PTS 差值调度并增加相同的初始等待；低延迟默认使用自适应音频缓冲并立即输出视频，硬件不保证接受低延迟请求。手动缓冲可覆盖模式默认值，选择自适应或 50–500 毫秒（50 毫秒一步）。
- 原生缓冲不是正负音画偏移。当前原生接口没有带正负号的音频偏移控制或共享音频播放时钟；相同初始等待只是近似配合，不代表已校准口型同步。接收中修改镜像设置会先询问是否重启；当前播放停止后，需要从手机重新连接。

## 失联恢复与接收端身份

- PIN 功能已从界面移除，所有启动 / 重启路径均不要求 PIN；升级时也不会沿用旧 PIN 开关。同网设备可连接，仅限可信家庭网络。
- **失联会话恢复**默认 15 秒，界面另提供关闭、30 秒、60 秒。仅媒体静默不能证明断线：镜像看门狗必须观察到最后一条控制 TCP 连接关闭，且整个宽限期没有新视频，才按失联处理。控制连接仍开着的已显示静止 / 暂停画面可一直保留。另有解码器停滞检查：收到可显示的视频数据后，整个宽限期没有解码输出，也可触发恢复。
- Wi-Fi 断开但 TCP 尚未报告关闭时，无法安全区分失联与静止画面，因此不承诺所有网络故障都能在 15 秒内恢复。此镜像看门狗不对媒体 URL / 纯音频会话做静默超时。恢复会清除旧画面 / 音频，并在前台仍要求接收时重启；不能强迫手机重新连接。
- **重置当前会话（保留身份）**提供手动恢复。普通停止 / 启动和自动恢复绝不会删除接收端密钥或轮换接收端身份。重启后也不要求 PIN。
- **重建接收端身份 / 重新配对**是独立的破坏性操作，必须明确确认。它停止播放，删除本应用的 AirPlay 接收端密钥与保存的 AirPlay 网络身份，重启后生成新身份。发送端可能需要重新查找并选择电视，手机可能还需删除旧条目。这是全局身份重建；原生接口没有发送端名称 / 已配对设备列表，也不支持逐设备撤销。

## 安全、构建与发布

应用不使用云账户、分析服务或摄像头 / 麦克风采集，接收端身份保存在应用私有存储。请勿把端口映射到互联网。DLNA 未提供控制认证，同一允许子网内的设备可以请求播放或改变应用内音量；AirPlay 原生监听所有可用接口，因此仅适用于可信局域网。媒体地址检查不构成完整的 DNS 重绑定防护；不提取受保护内容或凭据。完整网络限制与兼容性矩阵见 [英文详细文档](tv-receiver.md)。

使用 JDK 17 和 `.github/workflows/tv-receiver.yml` 固定的 Android SDK / 构建工具。构建命令如下；真实 Media3 JVM 检查需先通过 Gradle 解析依赖，并按环境设置 `JAVA_HOME` 与 `ANDROID_HOME`（SDK 35）。

以下保留 v0.3 构建/发布参考。当前集成源码还须运行 [GameStream 检查](tv-gamestream.md#source-build-and-validation)，
并遵循[签名与可选发布流程](tv-signing.md)：没有外部签名配置时，release 输出已改为
`tv-release-unsigned.apk`，不是下文历史命令中的已签名 `tv-release.apk`。未签名或开发用 debug APK
不能作为下一版 TV 发布。

```sh
python3 scripts/prepare_airplay_native.py
python3 scripts/prepare_airplay_source.py
python3 scripts/run_unit_tests.py
python3 scripts/run_tv_unit_tests.py
python3 scripts/run_airplay_unit_tests.py
python3 scripts/run_tv_audio_tests.py
./gradlew :tv:assembleDebug :tv:assembleRelease :tv:lintDebug :tv:lintRelease :tv:testDebugUnitTest
python3 scripts/run_tv_media3_audio_tests.py
python3 scripts/verify_tv_apk.py tv/build/outputs/apk/release/tv-release.apk
```

以上是验证步骤，不表示最终 v0.2 CI 已通过。发布门槛应包括 Java 17 构建 / lint、可移植裁剪 / 会话 / 协议 / PCM 测试、实际 Media3 流水线与音频输出包装层测试、原生与 APK 内容校验、`apksigner` 和 `zipalign`。Gradle 单元测试任务没有额外 Android 测试源，行为覆盖来自可移植测试脚本。PCM 测试覆盖全部 21 个偏移、采样率、声道、分块与生命周期；Media3 1.5.1 集成检查覆盖清空 / 重置 / 结束及防绕过。它们不打开真实音频输出，不测量音画同步。

v0.2 的固定原生源码与二进制保持不变，通过已有 JNI 接口实现接收控制；没有声称重新编译原生引擎。AirPlay 基于 jqssun/android-airplay-server / UxPlay，遵循 GPLv3；Media3 为 Apache-2.0。精确版本、SHA-256 和保留的许可文件见 `native/airplay/`。发布附件包括 APK、对应源码包与 SHA256SUMS，保留历史发布、不覆盖旧附件，并用 CI 运行与提交标识。完成构建、验证与源码准备后，`scripts/package_tv_release.py` 从干净且已提交的检出打包；脚本本身不执行构建 / 检查 / 发布。工作流发布后再次下载并校验哈希。预览调试签名的升级风险仍适用。

## 仍需实机验收

尚未声明任何真实设备互通、延迟或音画同步验证。请在电视检查：

- 冷启动与遥控焦点；实时裁剪保存 / 取消 / 复原、四边与缩放 / 平移边界、横竖屏及不同来源共用 APP 级选择。
- 普通 / 宽黑边、暗场、锁定后新字幕 / 浮层、重新检测与恢复完整画面。
- 无 PIN 自动启动及重连、手动恢复、身份重建的取消 / 确认、带声音的横竖屏镜像、暂停 / 继续 / 重连。
- 超过看门狗时间的静止 / 暂停画面、Wi-Fi 中断、解码停滞、主动断开，以及旧画面 / 音频是否清除。
- DLNA MP4 / HLS 定位 / 暂停 / 音量、AirPlay HLS、双来源接管、网络切换、停止后无残留播放、离开应用 / Home 后无音频或监听、重新进入；播放中返回菜单应继续播放。
- Media3 −500 / 0 / +500 毫秒的拍手 / 闪光对照、定位与播放结束、HDMI 输出、模式 / 原生缓冲切换。实际延迟与口型同步须另外测量。
- 长时间播放、丢帧与温度表现。

记录电视型号、Android 版本、发送设备 / 系统、应用、编码与内容类型即可，无需个人画面采集。

## 可复跑的真实 APK 界面验证

单独的 `androidTest` APK 提供框架级遥控 / 截图测试，不进入发布 APK。
构建 `:tv:assembleDebug :tv:assembleDebugAndroidTest` 后，可用
`scripts/run_tv_ui_validation.py` 在一次性 Android 模拟器（优先 Android TV）中运行。
脚本拒绝真实设备，需明确传入清理测试应用数据开关；分别验证中英文界面、自动启动、
无 PIN 配置、全局裁剪记忆、返回 / 取消 / 重开，以及可选的本地生成 DLNA 视频解码，
生成实际 Android 截图和带校验和的报告。CI 只编译测试 APK，不自动把它算作设备测试通过。
这不等于实体手机互通、真实局域网发现、HDMI 或音画时延验收。

加 `--offline` 会跳过局域网 / 解码前提，并明确将播放导航标注为测试注入的会话状态；
仍实际运行 Activity、遥控按键、弹窗、全局偏好和截图，不能算作 AirPlay / DLNA / 视频解码通过。
实际结果与截图见 [v0.3 界面验证记录](tv-ui-validation-v03.md)。
