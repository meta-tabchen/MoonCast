# MoonCast 0.9 / code66 development candidate

This is not a release announcement. Public 0.8 assets/tags remain unchanged.
Package `com.mooncast.community` and the existing community test certificate remain fixed.
The public fixture provides upgrade continuity, not publisher authentication.

## Implemented candidate behavior

- Manual floating controls work outside MoonCast when the user enables overlay permission: drag to an edge, expand, pause/resume picture and captured audio, restore the phone, or stop. The ongoing notification is the fallback. Whole-screen Android capture may include the small bubble; `FLAG_SECURE` is deliberately avoided because it can produce a captured black rectangle.
- **Minimum-brightness window control** is a separate, clearly named manual action. Its transparent overlay requests `screenBrightness=0` without modifying global brightness or adding secure/opaque capture masks. The complete first wake gesture is consumed; Stop/disconnect, screen-off, permission changes and window-owner death retire the override. Portable state tests pass; actual WindowManager/touch/pixel tests are being run separately. Minimum physical luminance, Douyin and power savings are not inferred from screenshots.
- **Physical screen-off is currently gated unavailable in the candidate** pending target-device wake, privilege-loss and stop/crash restoration validation. This is a safety gate, not completion of the requested feature. The following test/lease design is implemented but not enabled for general use.
- Panel recovery now has a dedicated `:panel` process, separate from mandatory `:host` capture teardown. It owns the touch guard and separate Root/Shizuku power helper; owner death requests restoration. A pure state regression covers bounded attempts, stale replies, delayed-OFF quiescence gating, disconnect invalidation and recovery without assuming timeout means success. Visible recovery confirmation remains disabled until an ordered ON or terminal helper acknowledgement proves no delayed OFF can still execute; A successfully persisted armed marker is required before OFF; interrupted/uncertain recovery quarantines future OFF across service restarts, and visible dismissal never reuses an old helper still restoring. Full-gesture and physical recovery behavior require device tests. This architecture remains gated: it has not passed physical-device fault injection, and a vendor power call returning is not optical proof.
- The phone stays bright by default. There is no automatic panel-off on start or reconnect. Physical panel-off requires an available Root/Shizuku helper, overlay permission, an active session and a per-session device check. The first attempt is a 15-second safety test after a cancellable 3-second countdown. A transparent guard consumes the first return touch. Only the user seeing the phone restored can confirm the touch path; hardware input while the panel is off is not guaranteed by Android. Power-key/double-tap behavior is not claimed.
- After successful device confirmation, manually requested panel-off can continue while casting, with a renewable helper lease. Restoration cancels renewal and another manual action is needed to turn it off again. Lost ownership, disconnect and stop request restoration. Helper crash/vendor display behavior still requires target-device validation.
- One device-name setting is used across phone/TV advertising. Busy-session changes are saved for the next start, without replacing UUID, certificates or pairing identity. A Moonlight application card is a stream title, distinct from the host/device identity.
- GameStream respects the client's negotiated viewport/FPS; it does not force 4K. Capture size is recomputed from live outputs so a 4K→1080p/720p transition can reduce input work. The TV shows physical display mode separately from requested and actual decoded video. A 4K TV output mode does not prove a 4K stream.
- Receiver lifecycle/native-session/decoded-frame events are retained in a bounded private timeline, with previous-process exit reasons where Android exposes them. No content, URL, network address, device name or pairing secret is recorded by this timeline. Nothing is uploaded automatically.

## Artifact provenance

Only APKs whose bundled native bytes match their associated rebuilt manifests may be called native-patched candidates. A plain unified build that consumes old pinned binaries is insufficient. Candidate source archives must identify the base Git commit and each generated native override; no source-only fix is presented as shipped.

- Diagnostic-only fixture options now separate reused/fresh decoder Surfaces and an explicitly requested no-callback texture-acquisition probe. Per-session sender transport diagnostics, received VCL, decoder outputs/drops, texture timestamps and pixels localize failures; send-call counts are not claimed as transmitted frames.

## Physical panel enablement matrix (not yet executed)

Keep `PHYSICAL_SCREEN_OFF_VALIDATED=false` until each explicitly supported phone/Android/OEM and Root/Shizuku backend is validated separately, with Douyin foreground and each actual cast protocol. Record exact APK hash, device/OS/backend, observed panel/touch behavior and failures.

1. Start/reconnect remains lit; countdown cancels; first-use 15-second recovery and deliberate confirmation work; sustained manual OFF spans multiple 30-second helper leases; manual restoration stays lit.
2. First DOWN through final UP/CANCEL, held/multi-touch and hardware-power interactions never accidentally reach the underlying application. No claim that power-key/double-tap works before observation.
3. Disconnect/Stop and kills of `:host`, `:panel` and privilege helper during countdown/OFF/ON, overlay/privilege revocation and Shizuku server stop: observe actual restoration, prompt media/input release and bounded helper cleanup.
4. Inject OFF/ON exceptions, hangs, delayed replies and silent vendor failure. Visible recovery dismissal stays disabled until command quiescence; no delayed OFF acts afterward. A permanently dark or blocked phone makes that configuration unsupported.
5. Failed armed/clear/quarantine persistence plus process restart preserve refusal/quarantine. Visible confirmation cannot start a replacement helper while an old recovery owner is still active.
6. Whole-screen and app capture do not introduce secure-window black masks or unintended private content. Pause/resume genuinely freezes/silences, then resumes current frames/audio without replaying buffered audio.

A vendor API return or emulator result is not optical-restoration evidence. Passing the portable state/journal tests does not satisfy this matrix.
