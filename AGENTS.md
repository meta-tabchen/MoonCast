# Working on MoonCast

Use **main** and the **`:unified`** application target. Start with README.md, [build/signing](docs/unified-build.md), [engineering pitfalls](docs/engineering-pitfalls.md), [release procedure](docs/release-process.md) and [version naming](docs/versioning.md). Browser behavior/evidence is in docs/browser-receiver.md and docs/browser-validation.md. Older sender/build/test records remain historical.

## Engineering rules

- Preserve user edits and upstream headers, licenses, source locks, binary hashes and rebuild provenance. Native source-only edits do not change shipped binaries. App code is under app/src/main/java/com/mooncast/host; io/github/jqssun adapters preserve upstream JNI ABI.
- Resolve **actual unified release dependencies and final APK contents**, not only declared module versions. Use the Bouncy Castle BOM-compatible set: bcpkix/bcutil **1.85**, bcprov **1.85.2**; do not assume matching version strings. Test fresh and existing identity handling in temporary directories and verify the APK DEX reference closure. Never delete user pairing/certificate data to make startup pass.
- Diagnose regressions against the **actual working 0.4.6 artifact**, not an unrelated Git parent such as 0.3.1. Record tested artifact hashes/versions and separate source-level, host, APK, emulator and physical-device evidence.
- Keep English and Chinese resources synchronized. Check phone protocol tabs at 320/360dp in both languages and larger font scales: equal-width two-line labels, intentional word wrapping, no clipping. Check repeated actions, Cancel/Back and current-option selection.
- Browser fullscreen capability/permission failure must fall back to page-level immersion, auto-hide controls, touch restoration and safe-area layout. Do not promise control of Safari/browser system bars or count an emulator as physical iPhone validation.
- Report GameStream startup failures proactively before host teardown; do not depend solely on a slow UI poll that can miss a short-lived process. Preserve bounded cleanup, useful error categories, held-input release and volume recovery.
- Capture, audio, input and Root are separate opt-in permissions. Input defaults off. Preserve stop/error cleanup and source-app capture restrictions. Work autonomously within explicit user authorization; never bypass a denial, permission boundary or security check.
- Run relevant :unified build/lint, scripts/run_unit_tests.py, scripts/check_localization.py, scripts/verify_unified_apk.py and scripts/verify_community_identity.py checks. Test browser-page and Android-sender paths separately; preserve JNI Zero JniInit in shrunk APKs. Device-dependent changes need device evidence or an explicit untested statement.
- Never describe compilation/static checks as interoperability, security, latency or lossless validation. A skipped/not-run/timed-out device job is not a pass; report failed subchecks even when another job succeeds. Version 0.7 uses versionCode 57; final artifact/CI status is tracked in docs/release-0.7-validation.md. Do not convert host/fixture checks into a user-device acceptance claim.

## Identity, source and publication

- Keep `com.mooncast.community` and the existing fixed public test certificate (SHA-256 `290e4372fff33c00848758b12275936900b2eccad053dc63c18622e1a1222bb2`). Do not generate a new key or silently substitute one. Missing/changed fixture or certificate checks must fail. A future production identity must be separate and never fall back to this public fixture.
- Exclude local.properties, caches, private credentials, private production keys, phone serials, pairing identities, private logs, live LAN links/QR tokens and personal screenshots from commits/releases. The sole public-key-material exception is the existing owner-initialized community Git fixture; do not include its app-signing PKCS12 in Release source archives. Public fingerprints/manifests are allowed; unrelated upstream cryptographic test fixtures retain their provenance.
- Explicit `-PmooncastUnsignedVerification=true` produces an unsigned, separate `com.mooncast.community.verification` artifact, not a community release or upgrade path.
- VersionName is the user's exact two- or three-component numeric choice. For the current AirPlay repair use **0.7.2**, code **59**, tag **v0.7.2**. Published 0.7/code57 remains historical. No browser/community/preview suffix. Increment versionCode independently. Keep old tags, assets, links and evidence labels unchanged.
- Publish through one designated writer: compare remote refs before each mutation, reconcile concurrent work, never force-push over it. After authorization, complete the bounded release workflow, verify public downloads/hashes and report exact CI status. Both ARM64 and ARMv7 belong on the Release with bilingual notes, source/notices, SHA256SUMS and the requested Latest classification. Latest is not a stability claim.
- If local/public commit IDs differ, prove the exact same Git tree and publish an honest source/build mapping; do not claim an unavailable local commit is publicly browsable. Keep runtime/source/documentation identities distinct where required.
- WebRTC source scope is in native/webrtc/SOURCE_LOCK.json and docs/browser-release-source.md. Application source plus pinned external SDK source/DEPS/build mapping is not a full offline SDK checkout or proof of independent SDK rebuilding. QR quality ceilings and capability reports are not measured throughput or sustained quality. Preserve original notices and historical media labels.
